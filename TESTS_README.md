# Проверки TenderHack

Запуск из корня репозитория при работающем API:

```powershell
.\backend\.venv\Scripts\python.exe run_tests.py --repo . --base-url http://127.0.0.1:8001
```

Без API запускаются только независимые проверки характеристик:

```powershell
.\backend\.venv\Scripts\python.exe run_tests.py --repo .
```

В CSV 738 сценариев. Дополнительно включены SRC-0001–SRC-0598: 373 проверки числовых границ, 193 допустимых перечисленных значения, 16 переводов единиц и 16 повторов эквивалентной величины в разных единицах. Все взяты из XML существующей поставки, внешних данных нет. Исходные 120 опираются на XML КТРУ и требования встречи с жюри. Новые API-001–API-020 проверяют валидацию, недопустимые подтверждения, отсутствие смешивания состояния между запросами, сохранение дополнительных сведений и введённых характеристик, неизвестные значения. Для успешных запросов также проверяются схема ответа и ограничения выдачи конечного кода. Ожидания этих тестов задаются контрактом API, а не текущими предсказаниями модели.

`test_report.json` содержит отдельный результат каждого сценария. PASS — выполненные утверждения прошли; FAIL — нарушены; BLOCKED — ресурсы недоступны; REVIEW — автоматического сценария пока нет. REVIEW нельзя считать успехом. Проверки безопасности выбранного кода могут пройти без получения конечного кода; это не свидетельство успешного разрешения товара.

Последний запуск 11.10.2026: 667 PASS, 30 FAIL, 0 BLOCKED, 41 REVIEW. Все 677 проверок HTTP поиска/характеристик прошли; также прошли 20 контрактных проверок API. 30 FAIL относятся к отдельной проверке AlgorithmC: допустимые числовые перечисления (например, ростовая группа) возвращают unknown; backend/API для этих же запросов проходят. В отчёте есть offline_status и live_status, чтобы не смешивать этапы. Это не процент точности ML-модели.

Контролируемые диалоги (отдельно от CSV; синтетический каталог с известным правильным ответом):

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest tests/test_correction_http.py tests/test_context_values_http.py tests/test_cd_http.py tests/test_stage2_followup.py -q
```

Последний результат: 59 passed. Эти проверки покрывают принятие/отклонение исправлений, конфликты значений, уточнения и смену состояния. Они не доказывают точность ранжирования реального каталога.

Остаются отдельные приёмочные проверки жюри: уникальность кода при незаполненных обязательных свойствах, повторное использование новых названий характеристик и сквозной пользовательский сценарий. Текущий stateless API сам по себе не предоставляет постоянного реестра новых характеристик. Их нельзя объявить проверенными только потому, что API отвечает HTTP 200.

Ручной чек-лист: MANUAL_TESTS.md — 27 сценариев с исходными REAL/SRC-кейсами, шагами и критериями успеха. Оставшиеся REVIEW не объявлены автоматически успешными. Отдельный набор из 30 реальных карточек запускается через run_real_tests.py; его результаты описаны в REAL_TESTS_README.md.
