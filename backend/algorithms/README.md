# algorithms — алгоритмы C и D

Два алгоритма поверх очищенного справочника КТРУ (`ktru_clean`). Зависимостей нет — только стандартная библиотека Python.

- **AlgorithmC** — строгая совместимость и сужение пула конечных кодов КТРУ.
- **AlgorithmD** — выбор следующего уточняющего вопроса, когда C не смог оставить один код.

Место в пайплайне (по схеме из `TenderHack_Implementation_Pipeline_Updated`):

```
текст товара ──► A (модель): факты ──► сопоставление свойств ──► ┌───────────┐
                                                                │ AlgorithmC│ ──► не уникально ──► ┌───────────┐
пул кандидатов от B ───────────────────────────────────────────►└───────────┘                     │ AlgorithmD│
                                                                        ▲                         └───────────┘
                                                                        └──── ответ пользователя ──────┘
```

## Файлы

| Файл | Что это |
| --- | --- |
| `AlgorithmC.py` | сам алгоритм C: проверка значений, диапазоны, единицы, вердикты, семь флагов, трасса |
| `AlgorithmD.py` | сам алгоритм D: выбор вопроса, остановка при неразличимых ограничениях |
| `contract.py` | контракт данных: `Fact` (вход от модели), `Pool`, `CResult`, `Question`, единицы, строковый мост |
| `ktru_index.py` | индекс справочника: позиции, семейства, типизированные ограничения, нормализация имён |
| `validation_run.py` | прогон стадия A → C → D на образце вывода модели и на карточках СТЕ |
| `validation_tests.py` | 25 проверок C и D: синтетика + мини-справочник |
| `prepare_samples.py` | одноразовая сборка образцов и мини-справочника из выгрузок организаторов |
| `prepare_stage_model_sample.py` | одноразовая сборка образца вывода модели (пока модель не готова) |
| `samples/` | данные для валидации: мини-справочник, карточки СТЕ, образец вывода модели |
| `data/` | полный корпус `ktru_actual_all.jsonl.gz` и словари единиц (14 МБ, в git не обязателен) |
| `validation_report.json` | результат последнего прогона валидации |

## Запуск

```bash
# проверки (корпус не нужен, используется samples/ktru_mini_index.json)
python -m algorithms.validation_tests

# валидация: образец вывода модели + 120 карточек СТЕ по каждому направлению
python -m algorithms.validation_run --cards 120

# быстро и без полного корпуса
python -m algorithms.validation_run --fixture --cards 20
```

## Использование

```python
from algorithms import AlgorithmC, AlgorithmD, KtruIndex, Units, Fact, Unit

index = KtruIndex.load()          # ищет data/ktru_actual_all.jsonl.gz
units = Units.load()

# 1. пул кандидатов раскрывает стадия B (лексический поиск + связи)
pool = index.family_pool("28.24.11.000-00000003")

# 2. факты приходят от модели (стадия A) после сопоставления свойств
facts = [
    Fact(kind="text",   value="От сети", name="Тип питания", extraction_confidence=0.95),
    Fact(kind="number", value=0.65, name="Мощность",
         unit=Unit(code="2355", text="кВт"), extraction_confidence=0.9),
]

result = AlgorithmC.run_c(pool, facts, index, units, type_verified=True)
result.survivors                  # ['28.24.11.000-00000001']
result.flags.to_dict()            # ktru_unique, value_verified, fields_complete, blocking_issues…
result.to_dict()                  # готовый к отдаче JSON

# 3. если код не уникален — спрашивает D
question = AlgorithmD.next_question(
    result.survivor_positions(index),
    AlgorithmD.answered_from_facts(facts),
    index,
    type_verified=True,
    blocking_issues=result.flags.blocking,
)
question.to_dict()                # вопрос либо stop_reason
```

## Вход от модели (контракт `Fact`)

Обязательные поля: `def_id`, `kind`, `value`, `unit`, `extraction_confidence`, `polarity`.
Необязательные: `name`, `operator`, `negation`, `span`, `extraction_method`, `definition_alternatives`, `fact_id`.

```json
{ "fact_id": "f7", "def_id": "5c54e4eb-4", "name": "Максимальный кровоток, л/мин",
  "kind": "number", "value": 0.65, "unit": { "code": "2355", "text": "кВт" },
  "operator": null, "polarity": "affirmed", "negation": null,
  "extraction_confidence": 0.86, "span": [12, 22] }
```

- Единицу переводить не нужно: `кВт → Вт` сделает C. Присылать как в тексте плюс код ОКЕИ, если он известен.
- `extraction_confidence < 0.6` — факт проверяется, но **не исключает** код.
- Строковый мост `fact_from_string("Мощность: 0,65 кВт")` даёт уверенность 0.5: работает, пока модель отдаёт строку, и не ломает точность молча.

## Что зашито в C

1. Исключает код только подтверждённая несовместимость. Отсутствие факта, отсутствие свойства в позиции, неизвестная единица и низкая уверенность дают `unknown`.
2. Перевод только внутри размерности: `кВт → Вт` можно, `кг → Вт` нет. Контекстные алиасы (`мин`, `мин-1`, `с`) без контекста не применяются.
3. Строгие границы: `>1.25` отсекает ровно `1.25`, `≤1.25` её принимает.
4. Пользовательский интервал должен целиком лежать внутри каталожного; частичное пересечение — не подтверждение.
5. Альтернативы одного свойства — «ИЛИ»; значения с разными единицами не смешиваются.
6. Позиции с `resolve_blocked` (шаблоны, без характеристик, дефект источника) из сужения исключаются и считаются отдельно.
7. `selected_ktru_code` заполняется только при `type_verified ∧ ktru_unique ∧ fields_complete ∧ value_verified ∧ catalog_scope_complete` и отсутствии блокировок.

## Что зашито в D

1. Порядок: конфликт/блокировка → подтверждение типа → свойство-разделитель → обязательные поля.
2. Группировка по **множеству** допустимых значений, а не по «значения разные».
3. Свойство спрашивается, если оно сужает оставшихся; позиции без этого свойства ответ не исключает и учитываются в худшем случае.
4. Одинаковая структура ограничений у всех кандидатов — вопросы по значениям запрещены (`value_indistinguishable`).
5. Уже заданные свойства (включая `definition_alternatives`) не спрашиваются повторно.

## Результат валидации (`--cards 40`)

| Направление | Карточек | Дошло до 1 кандидата | Пул в среднем |
| --- | --- | --- | --- |
| инструменты | 15 | 13 | 3–4 |
| мебель | 40 | 4 (+32 неоднозначных) | 3–6 |
| одежда | 33 | 7 (+15 неоднозначных) | 6–9 |

- Ложных исключений (когда C выкидывает все позиции) — 0.
- `selected_ktru_code` почти везде `None`, потому что `fields_complete = false`: у позиции есть обязательные характеристики, которых нет в описании товара. Это ожидаемое поведение — резолв требует полноты карточки, а не только уникальности кода.
- Узкое место — не C и D, а стадия сопоставления: в этой заглушке 20–30 % фрагментов получают `def_id`, остальные неоднозначны. По мере готовности модели и словаря свойств этот процент определяет качество всей цепочки.

## Границы

- Матрица единиц (`DIMENSIONS` в `AlgorithmC.py`) покрывает 25 размерностей, встречающихся в КТРУ; алиасы из `data/example_unit_strings.json` закрывают 81,7 % написаний из примеров. Неизвестная единица возвращается как неопределённая, а не подставляется по похожести.
- Поиск пула в `validation_run.py` (`pool_by_title`) — грубая заглушка вместо BM25 + эмбеддингов: пересечение слов названия с именами характеристик семейства.
- Дефекты исходной выгрузки (7 позиций) не исправляются: позиция блокируется через `resolve_blocked` и не участвует в сужении.
