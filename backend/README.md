# TenderHack Казань 2026 — стартовый backend

FastAPI + PostgreSQL + SQLAlchemy 2 + Alembic. API для автозаполнения характеристик СТЕ и сужения кода КТРУ. Файлы [контракта для фронта](docs/API.md) и [исследования](docs/RESEARCH.md) — часть проекта.

## Запуск

```bash
docker compose up --build
```

Команду запускать из корня репозитория. Проверка: `http://localhost:8000/api/docs`, `http://localhost:8000/api/health/ready`, `http://localhost:8000/api/v1/catalog/status`. Compose запускает миграцию перед API. По умолчанию пароль тестовый; для совместной среды задать `POSTGRES_PASSWORD` и ограничить доступ. Разрешённые CORS origins: `CORS_ORIGINS` через запятую. По умолчанию localhost:3000 и localhost:5173.

До появления данных каталог пуст. Для проверки интерфейса можно **явно** загрузить синтетический набор:

```bash
docker compose cp backend/demo-catalog.json api:/srv/demo-catalog.json
docker compose exec api python -m app.import_catalog /srv/demo-catalog.json
```

После этого `POST /api/v1/analyses` с примером из `docs/API.md` вернёт `resolved` и код `DEMO-CUP-PAPER`. Эти коды не принадлежат настоящему КТРУ. Загрузчик принимает нормализованный JSON по образцу `demo-catalog.json`; повторный запуск обновляет строки по кодам/именам, загрузка атомарна. Сейчас импорт не удаляет устаревшие строки; перед реальной массовой загрузкой определить политику версий и удаления. Файл источника не должен включать секреты или персональные данные.

## Разработка и тесты

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
docker compose up -d db
export DATABASE_URL='postgresql+psycopg://tenderhack:tenderhack@localhost:5432/tenderhack'
alembic upgrade head
pytest -q
uvicorn app.main:app --reload
```

`app/analysis.py` — простой детерминированный базовый алгоритм по уже нормализованным характеристикам. Он не извлекает признаки из описания, не исправляет опечатки, не конвертирует единицы и не является ML моделью. Получение официальных данных также пока не реализовано. Реальную схему файла организаторов адаптировать в отдельном конвертере, не менять HTTP ответы без синхронного обновления `docs/API.md`.

## Следующий промпт для Codex в репозитории команды

> Проверь структуру текущего репозитория и `AGENTS.md`. Интегрируй backend из этого проекта в существующую структуру без удаления чужих файлов. Сохрани HTTP контракт `docs/API.md`. Подключи предоставленный организаторами датасет через отдельный валидируемый конвертер в формат `demo-catalog.json`, но не загружай демонстрационные коды как реальные КТРУ. Покрой тестами повторную загрузку, неоднозначность, ошибочные единицы и пустые данные. Измени `docs/API.md` в том же коммите при каждом изменении endpoint, поля или статуса. Покажи diff и команды проверки; не предполагай формат датасета, сначала изучи его заголовки и примеры.

## Следующие решения команды

- Уточнить структуру датасета, официальные идентификаторы характеристик и требуемую метрику.
- Согласовать с фронтом UX для `needs_data`/`needs_input`/`ambiguous`.
- Заменить базовый алгоритм модельным адаптером, определить пороги уверенности на отложенной выборке.
- Перед публичным размещением добавить авторизацию, лимиты и защиту от произвольных больших `raw_payload`.
