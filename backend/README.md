# TenderHack Казань 2026 — стартовый backend

FastAPI + PostgreSQL + SQLAlchemy 2 + Alembic. API для автозаполнения характеристик СТЕ и сужения кода КТРУ. Файлы [контракта для фронта](docs/API.md) и [исследования](docs/RESEARCH.md) — часть проекта.

## Запуск

```bash
docker compose up --build
```

Команду запускать из корня репозитория. Проверка: `http://localhost:8000/api/docs`, `http://localhost:8000/api/health/ready`, `http://localhost:8000/api/v1/catalog/status`. Compose запускает миграцию перед API. По умолчанию пароль тестовый; для совместной среды задать `POSTGRES_PASSWORD` и ограничить доступ. Разрешённые CORS origins: `CORS_ORIGINS` через запятую. По умолчанию localhost:3000 и localhost:5173.

До появления данных каталог пуст. Для проверки интерфейса можно **явно** загрузить синтетический набор:

```bash
docker compose cp backend/demo-catalog.json api:/srv/demo-catalog.json
docker compose exec api python -m app.import_catalog /srv/demo-catalog.json
```

После этого первый `POST /api/v1/analyses` с примером из `docs/API.md` вернёт `needs_input` и кандидата `DEMO-CUP-PAPER`. После ручной проверки категории повторите запрос с `confirmed_ktru_code`: только совместимый код при заполненных обязательных характеристиках и отсутствии ошибок даст `resolved` и `result.confirmed_by_user=true`. Название и описание не проверяются алгоритмом. Эти коды не принадлежат настоящему КТРУ. Загрузчик принимает нормализованный JSON по образцу `demo-catalog.json`; повторный запуск обновляет строки по кодам/именам, загрузка атомарна. Импорт не удаляет категории, определения характеристик и СТЕ, отсутствующие в файле; правила категорий обновляются по контракту ниже. Файл источника не должен включать секреты или персональные данные.

## Разработка и тесты

Начните в корне репозитория: первая команда переводит в `backend/`, остальные выполняются оттуда. Compose файл находится в корне и указан явно через `-f ../docker-compose.yml`. PostgreSQL из Compose доступен локально на `127.0.0.1:5432`.

```bash
cd backend
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
docker compose -f ../docker-compose.yml up -d db
export DATABASE_URL='postgresql+psycopg://tenderhack:tenderhack@localhost:5432/tenderhack'
alembic upgrade head
pytest -q
uvicorn app.main:app --reload
```

Повторный импорт сохраняет идентификаторы и обновляет строки. Поле `attributes` внутри каждой категории имеет три режима:

- Переданный непустой список полностью заменяет правила категории: обновляет перечисленные правила и удаляет отсутствующие.
- Явное `"attributes": []` очищает все правила категории.
- Отсутствующее поле `attributes` сохраняет существующие правила без изменений; у новой категории правила остаются пустыми. Другие поля категории обновляются как обычно. `null` не принимается.

Категории, определения характеристик и СТЕ, отсутствующие в файле, сохраняются. Неверные ссылки, повторные правила, конфликтующие имена/синонимы, неверные числовые допустимые значения и некорректная иерархия откатывают весь импорт. `value_type` принимает только `text`, `number`, `boolean`.

Если Docker недоступен, для локальной проверки миграций и API можно задать `DATABASE_URL=sqlite:///./local.db`, затем выполнить `alembic upgrade head`, `pytest -q` и `uvicorn app.main:app`. Это не заменяет проверку PostgreSQL/Compose перед слиянием. В PowerShell переменные задаются через `$env:DATABASE_URL`, окружение активируется командой `.venv\Scripts\Activate.ps1`.

По умолчанию тесты используют временную SQLite БД и реальные миграции. Для проверки тех же сценариев на PostgreSQL задайте `TEST_DATABASE_URL` с URL тестовой БД и запустите `pytest -q`. Для каждого теста создаётся отдельная схема `test_<uuid>`, которая удаляется после проверки; пользователю БД нужно право создавать схемы.

`app/analysis.py` — простой детерминированный базовый алгоритм по уже нормализованным характеристикам. Он не извлекает признаки из описания, не исправляет опечатки, не конвертирует единицы и не является ML моделью. Получение официальных данных также пока не реализовано. Реальную схему файла организаторов адаптировать в отдельном конвертере, не менять HTTP ответы без синхронного обновления `docs/API.md`.
