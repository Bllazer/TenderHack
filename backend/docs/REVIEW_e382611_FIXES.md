Ответ accept:<name> меняет только имя, затем все факты проверяются заново; 650/900 Вт дают конфликт. reject сохраняет сведения без сопоставления. Старый ответ не действует после изменения факта/категории; обычные дополнительные сведения допустимы. Контекст товар/упаковка сохраняется.

Backend самостоятельно проверяет обязательные checks, неопределённых конкурентов, тип, код, область, исходные блокировки и issues. Индекс C/справочник единиц создаются один раз в lifespan из snapshot, запросы ничего не перечитывают.

C исправляет пустые/перевёрнутые/строгие интервалы, включение всего требования, OR с отдельными единицами, эквивалентность числовых фактов, обязательные unknown/low confidence и сохранение заблокированных конкурентов. kind=3 остаётся unknown. Числовые переводы используют Decimal без размытия границ. D собирает варианты всего пула и добирает обязательное поле у единственного кандидата. Старые штатные tests C/D обновлены: позитивные факты теперь заполняют все обязательные поля; небезопасные ожидания удалены без ослабления проверок.
