## Что исправлено

Compose монтирует `catalog-build`, а не пустой `catalog`. Пути хоста настраиваются
через `TENDERHACK_CATALOG_PATH`, `TENDERHACK_MODEL_PATH`,
`TENDERHACK_CLEAN_SUPPLY_PATH`; внутренние пути фиксированы и описаны в README.
Модель и индекс исключены из Docker build context. Один API worker, без БД,
сессий и сохранения анализов. Healthcheck проверяет readiness.

Первый полный запуск API завершился кодом 137, Docker временно отвечал 500 при
других работающих контейнерах. Уменьшена пиковая память загрузчика: JSON передаётся
Pydantic как bytes, SHA считается потоково. Целостность, данные и проверки
не ослаблены. Повторный `docker compose up --build -d` прошёл; API занимал примерно
3,1 ГБ после загрузки. Другие приложения не останавливались.

Реальная нефть без характеристик выявила тупик `needs_input` без вопроса.
При отсутствии вопроса и наличии непроверяемой позиции в оставшемся пуле теперь
возвращается `needs_data`, issue `catalog_constraints_unavailable` и конкретный
следующий шаг: исправленная поставка или смена типа. Ручной код это не обходит.
Контракт обновлён в API.md; добавлены четыре HTTP-регрессии.

  отклонение сохраняет дополнительные сведения. Явная правка конфликтующего

- Контур дыхательный с неподдерживаемыми ограничениями → needs_input с вопросом,

  не даёт resolved. Чай и дрель остаются needs_input по проверенным HTTP-запросам:

## Ручная проба, остановка и перезапуск

Открыть http://localhost:8080. Вставить одно описание, подтвердить предложенный
тип и затем конечный код. Чтобы увидеть вопрос характеристики, начните с одного
названия товара и ответьте соответствующим значением из таблицы выше.

```text
Битум нефтяной строительный; Марка: БН 70/30
Глина огнеупорная; Марка глины огнеупорной: ПГА
Шпажки для шашлыка; Материал: Дерево
```

Из корня репозитория:

```powershell
docker compose stop
docker compose up -d
docker compose logs --tail 30 api
```

После изменений кода: `docker compose up --build -d`. Ожидайте readiness: полный
snapshot требует памяти и времени, особенно при других активных контейнерах.
Ресурсы остаются на хосте и повторно не пересчитываются.

Проверены три полных положительных типа, а не весь каталог. kind=3,
неизвестные единицы/семантика, source_issues и позиции без характеристик не дают
достоверного resolved. Неизвестный конкурент не доказывает уникальность другой
позиции. Поисковое ранжирование не является вероятностью или подтверждением
товарного типа; известные ограничения перефразировок сохраняются.
