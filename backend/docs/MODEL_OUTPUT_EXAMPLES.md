# Примеры вывода моделей A и B

Все примеры ниже — **не написаны руками**: это вывод функций на реальных артефактах.
Скрипт: `C:\hack\examples_model_outputs.py`, полный лог: `C:\hack\build\model_output_examples.txt`.

| Что | Значение |
|---|---|
| Позиция для модели A (примеры 1–4) | `28.24.11.000-00000003` «Дрель ручная электрическая»; свойства: Мощность (Вт), Напряжение (В), Высота (мм), Масса (кг), Тип застежки (текст) |
| Позиция для примеров «без имени» | та же `28.24.11.000-00000003`, но с **реальным** набором свойств: Тип питания, Минимальный и Максимальный диаметр зажима патрона (оба мм), Мощность (Вт), Напряжение аккумулятора (В), Максимальное количество оборотов (об/мин) |
| Позиция-шкаф | `31.01.12.139-00000002` «Шкаф деревянный для документов»: Высота (мм) |
| Индекс для модели B | `resources/catalog-build`, 14 550 категорий |
| Модель | `intfloat/multilingual-e5-small`, ревизия `614241f622f5…` |

Как читать вывод:

* `extraction_confidence` — уверенность факта; `≥ 0.6` факт **жёсткий** (C исключает по
  нему коды), `< 0.6` — **мягкий** (C проверяет, но не исключает);
* `extraction_method` — как получено имя: `exact` (точное), `typo` (уверенная опечатка,
  замена), `fuzzy` (неуверенная опечатка), `unmatched` (имя не найдено в справочнике);
* `bound_by_unit` в статистике — сколько значений привязано **по размерности единицы**,
  когда имени характеристики в тексте нет («дрель 650 вт» → Мощность);
* **перевод единиц делает C, а не извлечение**: факт сохраняет написание пользователя
  («0,65 кВт»), а сравнение с диапазоном позиции идёт в её единице (Вт);
* `def_id` — код характеристики в позиции; пустой, если имя не подтверждено однозначно;
* `raw` — **исходный текст пользователя**, он сохраняется всегда, даже после замены имени;
* в модели B `каналы` — какие каналы поставили документ в свой топ-50 (BM25 / E5 / CHAR),
  `score` — сумма `1/(60+ранг)` по каналам (RRF).

## 2. Модель A: значение **без имени** характеристики — «дрель 650 вт»

Реальный запрос: имени характеристики в тексте нет, но единица измерения её называет.
Если такая характеристика в позиции **одна**, значение принадлежит ей.

### 2.1 Мощность в ваттах

```
вход:  «дрель 650 вт»
факт:  {"kind": "number", "value": 650.0, "name": "Мощность", "def_id": "d4",
        "unit": {"code": "212", "text": "вт"},
        "extraction_method": "fragment+exact", "extraction_confidence": 0.95,
        "fact_id": "ste:0:0"}
статистика: bound_by_unit=1 with_def_id=1 unmatched=0 unparsed=0
```

```
вход:  «Дрель ручная электрическая 650 вт»      → то же: Мощность 650 вт, def_id d4
вход:  «дрель 650вт» (единица приклеена)        → то же: Мощность 650 вт, def_id d4
вход:  «650 вт» (только измерение)              → то же: Мощность 650 вт, def_id d4
```

### 2.2 Киловатты: сравнение идёт в ваттах

```
вход:  «дрель 0,65 кВт»
факт:  {"kind": "number", "value": 0.65, "name": "Мощность", "def_id": "d4",
        "unit": {"code": "214", "text": "кВт"},
        "extraction_method": "fragment+exact", "extraction_confidence": 0.95}
```

Единица остаётся как написана, а переводит её C перед сравнением с диапазоном позиции
(`500…800 Вт`): 0,65 кВт = 650 Вт → совместимо. Проверено тестом
`test_kilowatts_are_compared_in_watts` и тестом сквозного анализа
`test_power_in_a_query_without_a_name_is_counted_in_watts`.

### 2.3 Несколько измерений в одном тексте

```
вход:  «дрель 650 вт 220 в»
факт:  Мощность = 650 вт, def_id d4, fact_id ste:0:0
факт:  Напряжение аккумулятора = 220 в, def_id d5, fact_id ste:0:1
статистика: bound_by_unit=2 with_def_id=2
```

### 2.4 Когда привязки НЕТ (значение не выдумывается)

```
вход:  «дрель 12 мм»      в позиции ДВА свойства в миллиметрах
                          (минимальный и максимальный диаметр зажима патрона)
факт:  {"value": 12.0, "name": "дрель", "def_id": null,
        "unit": {"code": "003", "text": "мм"},
        "extraction_method": "fragment+unmatched", "extraction_confidence": 0.0}
статистика: bound_by_unit=0 unmatched=1
```

```
вход:  «дрель 30 кг»      массы у позиции нет вовсе
факт:  {"value": 30.0, "name": "дрель", "def_id": null, "unit": {"code": "166", "text": "кг"},
        "extraction_method": "fragment+unmatched", "extraction_confidence": 0.0}
```

```
вход:  «стол 750 мм»      у шкафа миллиметры только у «Высоты» → привязка есть
факт:  Высота = 750 мм, def_id t1
```

### 2.5 Неполное имя характеристики: привязывается само, но остаётся мягким

Имя написано не полностью, однако леммы факта — строгое подмножество лемм **ровно
одной** характеристики позиции.

```
вход:  «минимальный диаметр 12 мм»      ⊂ «Минимальный диаметр зажима патрона»
факт:  {"value": 12.0, "name": "минимальный диаметр", "def_id": "dmin",
        "unit": {"code": "003", "text": "мм"},
        "extraction_method": "partial_name", "extraction_confidence": 0.55,
        "polarity": "uncertain"}
       ← 0.55 < 0.6: C значение проверяет, но код по нему не исключает
```

```
вход:  «максимальный диаметр 15 мм»     → def_id «dmax», partial_name, 0.55
вход:  «Минимальный диаметр зажима патрона 12 мм» (полное имя) → exact, 0.95, жёсткий
вход:  «диаметр 12 мм»                  → привязки нет: подмножество подходит и минимуму,
                                          и максимуму → вопрос «Что означает «диаметр 12 мм»?»
```

Проверка на уровне пайплайна (фикстура с двумя характеристиками в мм):

| Текст | Что видно пользователю |
|---|---|
| «…минимальный диаметр 5 мм» | факт `минимальный диаметр = 5 мм` (мягкий), вопроса про измерение нет, `resolved` |
| «…минимальный диаметр 12 мм» (вне 1…10) | позиция **не исключена**: мягкий факт не доказательство, `resolved` |
| «…диаметр 5 мм» | вопрос с вариантами «минимальный / максимальный / дополнительные сведения» |

Модель A на том же входе: «минимальный диаметр 12 мм» → `dmin`, `fragment+partial`, 0.55;
«диаметр 12 мм» → `fragment+unmatched` (привязки нет).

## 8. Живая стадия A (`app/extraction.py`): факты и коррекции

Здесь видно, что именно уходит в API: факт (имя, значение, единица, `raw`) и коррекции.

| Вход | Факты | Коррекции | Не разобрано |
|---|---|---|---|
| `Мощность 650 Вт` | `Мощность = 650 Вт` | — | — |
| `650 Вт мощность` | `Мощность = 650 Вт` | — | — |
| **`дрель 650 вт`** | **`Мощность = 650 вт`**, raw=`650 вт` | — | `дрель` |
| **`дрель 0,65 кВт`** | **`Мощность = 0,65 кВт`**, raw=`0,65 кВт` | — | `дрель` |
| **`дрель 650 вт 220 в`** | **`Мощность = 650 вт`; `Напряжение аккумулятора = 220 в`** | — | `дрель` |
| `дрель 12 мм` (в позиции два свойства в мм) | нет — размерность неоднозначна | — | `дрель 12 мм` |
| `дрель 30 кг` (массы у позиции нет) | нет — размерности нет в области | — | `дрель 30 кг` |
| `стол 750 мм` (у шкафа мм только у «Высоты») | `Высота = 750 мм` | — | — |
| **`Мошность 650 Вт`** | **`Мощность = 650 Вт`**, raw=`Мошность 650 Вт` | **`Мошность → Мощность`, confirmation_required=False** | — |
| **`Мошность: 650 Вт`** | **`Мощность = 650 Вт`**, raw=`Мошность: 650 Вт` | **`Мошность → Мощность`, False** | — |
| `Машность 650 Вт` | `Машность = 650 Вт` (как написано) | — (вопрос задаст поток коррекций) | — |
| `Высата 2000 мм` | `Высата = 2000 мм` (как написано) | — (вопрос «Возможно, вы имели в виду «Высота»?») | — |
| `Машность Полиэстер` | нет (текстовое значение при неподтверждённом имени не выдумывается) | — | `Машность Полиэстер` |
| `Мощность 650 Вт напряжение 220 В` | `Мощность = 650 Вт`; `Напряжение = 220 В` | — | — |
| `дрелль 650 вт` | нет (название товара — не характеристика) | — | `дрелль 650 вт` |

Сквозная проверка «мощность считается в ваттах» (тесты `tests/test_pipeline.py`):
«Дрель; питание: от сети; 650 вт» + код `TEST-DRILL-MAINS` (диапазон 500…800 Вт) →
`status=resolved`; «0,65 кВт» → тоже `resolved`; «900 вт» → позиция попадает в
`excluded`, потому что 900 Вт из диапазона выходит. Если в области нет характеристики
такой размерности («12 мм» у дрели), измерение остаётся неразобранным и API сообщает
`unmapped_measurement` — значение не приписывается наугад.

Разница между моделью A и живой стадией A намеренная: модель A — офлайн-матчер, она
канонизирует имя в факте сама (0.90 или 0.58); живая стадия при неуверенности оставляет
**написание пользователя** и спрашивает человека, а при уверенности заменяет и пишет
провенанс.
