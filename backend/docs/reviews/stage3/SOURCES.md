## Что задано источниками

Лист2 трёх исходных XLSX содержит категорию ПП и код КПГЗ (A/B), имя и тип
характеристики (D/E/F), наблюдаемые значения карточек (G), единицу (H),
идентификаторы/имена связанных СПГЗ (I/J) и эталонные значения с ID (K).
Лист1 содержит реальные СТЕ и свободные записи их характеристик. Это наблюдения:
в частности, единицы и написания в них бывают ошибочными. Столбец G не принят
за нормативный словарь даже у строки с типом «Эталонная».

Точные SHA исходных XLSX и строки сохранены в
`backend/resources/card-schema-review.json`. Offline-адаптер проверяет SHA,
категорию и имя строки. Словарь СПГЗ берётся из K только при совпадении ID с I.
Хеш/длина наблюдений G остаются в артефакте; они не участвуют в C.

Проверенные строки: материал рукоятки/бойка молотка 24130/24164; материал
рабочей части/рукоятки киянки 23295/23327; материал черенка/полотна лопаты
39858/39860; подлокотники, материал сидения/спинки деревянного стула
3717/3719/3723; подлокотники металлического стула 3986; пол/капюшон/российский
размер зимнего пальто 8871/8873/8876; российский размер футболки 1221.
Строки цвета (24158/8894/1415) и пола футболки (1219) подтверждают наличие
поля карточки, но не полный нормативный словарь. Их небольшой проверенный
языковой словарь помечен `vocabulary_is_constraint=false`.

В adult-XML футболки свойство `3c32ae26-1` «Российский размер» имеет type=2,

это основание трактовки **designation**. Это не физическая длина и не count.
Разрешение не распространяется на произвольные числа без единиц.

## Что интерпретирует адаптер

Семь явных связей областей заданы отдельными review-записями и проверяемыми
якорями исходных характеристик, а не подбором по похожему названию во время
запроса. Это применимость схемы для карточки: молотки, киянки, строительные
лопаты, деревянные/металлические стулья, текстильное зимнее пальто взрослых,
взрослая трикотажная футболка. Официального crosswalk ПП ↔ КТРУ в XLSX нет,
такой статус не присвоен. Тип подтверждается прежним механизмом КТРУ.

В футболке КТРУ «Назначение» содержит Мужская/Женская/Универсальная. Отдельная
review-запись предпочитает это исходное поле дополнительному ПП-полу пола,
чтобы одно слово не создавало две искусственные привязки. Поле КТРУ не изменено.

«Деревянный» → «Дерево», «стальной» → «Сталь» — одобренные языковые алиасы
внутри фактического допустимого словаря выбранной области, не замена во всём
тексте. Формы рода/падежа сверяются существующим pymorphy3. Материал части
назначается только при явно связанном имени части; без него требуется решение.
«Без капюшона/подлокотников» становится допустимым значением отсутствия только
когда оно есть в исходном словаре; отрицание сохраняется в provenance.

## Что поддерживает проверка

Схемы карточки не попадают в Position.properties, индекс C или числовые
ограничения. КТРУ имеет приоритет. Backend и C повторно проверяют только
исходные нормативные правила; неизвестное не становится compatible.
В проекции C `canonical_absence` означает утверждение допустимого значения
отсутствия, а не отрицание этого значения. Клиент не может передать этот флаг.
Прежние приоритеты incompatible и блокировки источника/семантики сохранены.

Порожки не найдены по имени во всех 60 087 записях clean5
([результат](porozhki-coverage.json)). Это ограничение поставки. Их измерение
сохраняется без назначения; явно указанная толщина сохраняется как факт,
без выдуманной КТРУ-привязки. Другие товары не использованы как замена.
