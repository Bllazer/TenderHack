## Реализация и основания

Существующий `app.extraction` расширен контекстными формами и проверенными
алиасами. `app.card_schemas` готовит небольшой immutable-словарь offline из
исходных XLSX; lifespan загружает его один раз через существующий адаптер A.
ПП/СПГЗ дополняют карточку отдельно от нормативного C. Происхождение поля,
исходное написание и span возвращаются в API. Неоднозначный материал части,
назначение измерения и опечатка используют прежний механизм correction_flow.
Решение пользователя не обходит полную проверку.

Отрицание относится к конкретному фрагменту. Проверенное отсутствие выражается
исходным допустимым значением; непредставимое сохраняется неопределённым.
Предыдущие ответы сохраняются при смене категории, но mappings вычисляются
заново. Цвет и другие дополнительные поля остаются в карточке. Размер футболки
проверяется как designation по отдельному исходному правилу. Подробные
[основания](SOURCES.md), [14 повторных сверок XML](source-checks.json),
[контракт](../../API.md) и [хеши](artifacts.json).

Сохранены приоритет доказанного incompatible, неизвестность конкурирующего
кода, обязательные пропуски, блокировки источника и неподдержанного введённого
ограничения. В частности, явно указанный деревянный боёк проверяется как
недопустимый материал; он не переименовывается в рукоятку. «Деревянная пила»
не превращается в утверждение о допустимом обрабатываемом материале.

Prepared-сборку следует сначала проверить, затем переключать остановленный API,

использует резервную папку `.tools/catalog-before-stage3` для сравнения SHA.

Из корня: `docker compose up -d --build --no-deps api`.
Из frontend: `npm.cmd run build`, затем `npx.cmd --yes pnpm@11.25.0 test:e2e`
с `BACKEND_TEST_PYTHON`, указывающим на существующий backend/.venv Python.

## Реальная HTTP-приёмка

Рабочий API использует полный snapshot и настоящие локальные веса E5.
[До изменений](before.json) и [после](after.json) сохраняют полные тела.
Для контекстного A категория передана явно; рядом записаны результаты до
подтверждения. Это не приёмка поиска этапа 4.

| Описание | Полученная карточка / следующий шаг |
|---|---|
| молоток деревянный | фрагмент сохранён; уточнение назначения материала части |
| молоток с деревянной рукояткой | материал рукоятки = Дерево, отдельное поле ПП; дальше вопрос о типе молотка |
| киянка деревянная | материал требует выбора части: рабочая часть/рукоятка |
| пальто мужское синее, размер 48, без капюшона | Половой признак = мужское; Цвет = Синий; Российский размер = 48; Тип капюшона = Отсутствует; остаётся подтвердить код |
| лопата совковая без черенка | тип = совковая; отсутствие черенка сохранено неопределённым с причиной; отрицание не затронуло тип |
| ловпата совкавая | предложение Совкавая → Совковая; принятие проверяет тип, отказ сохраняет исходное |
| футболка мужская 40 размер / размер 40 / российский размер 40 | Назначение = мужская; Российский размер = 40 без единицы; остаётся подтвердить код |
| порожки напольные 3 мм | измерение = 3 мм, name пустое; роль не угадана, исходный товар сохранён |
| порожки напольные толщиной 3 мм | Толщина = 3 мм без КТРУ-привязки; семейство отсутствует в поставке |
| стул без подлокотников | Наличие подлокотников = Нет; дальше вопрос о мягком сидении |

Все эти первые ответы остаются needs_input: ручное подтверждение кода не
подставляется автоматически. [Полный диалог](flow.json) проверяет принятие и
отклонение назначения/опечатки, «не знаю», правку размера, физически неверную
единицу, конфликт и смену категории. После явной правки размера футболки с 40
на 42 и подтверждения конечного кода получен **resolved 14.14.30.110-00000002**.
Исходный текст 40 и происхождение правки сохранены.

Дополнительные семейства из трёх направлений: металлические стулья
`31.01.11.150-00000004` (Нет подлокотников), письменные столы
`31.01.10.000-00000006` (Угловой), зимние кожаные куртки
`14.11.10.000-00000006` (Женская), сабельные пилы
`28.24.11.000-00000024` (явно заданное Дерево как обрабатываемый материал).
Вопросы остаются конкретными: мягкое сидение, тип каркаса, натуральная кожа,
тип питания. Для «деревянной пилы» материал обработки не назначен.

При «Молоток с деревянным бойком» исключены десять позиций по собственному
проверенному правилу материала бойка. `25.73.30.141-00000012` не содержит
этого свойства и остаётся unknown. Его подтверждение не даёт resolved;
подтверждение исключённого кода получает 422. Это исправленная source-based
приёмка: первоначальное предположение о наличии правила у всех молотков
было неверным; ограничения production не изменялись ради теста.

Повтор этапов 1–2: [пять семейств](stage1-repeat/after.json),
[83 POST матрицы](stage2-matrix.json), [21 пограничный POST](stage2-edges.json),

Полные причины и блокировки сохранены в ответах. Последние независимые
