## Источник, интерпретация и поддержка

Первичные основания: «Описание структуры xml с КТРУ.docx» и «КТРУ xml.zip»
из поставки организаторов «Казань 2026», actual-части ЕИС от 2026-10-05.
Контрольные суммы оригиналов, clean5, каталога, индекса и весов —
[artifacts.json](artifacts.json). Выдержка из описания —
[xml-description-excerpt.txt](xml-description-excerpt.txt).

| Что утверждает источник | Что делает адаптер | Что проверяют backend и C |
|---|---|---|
| kind=3 — изменяемая характеристика, выбор нескольких значений | Сохраняет kind, required, каждый элемент allowed, его единицу и value_code | Каждый действительно выбранный элемент; повтор не конфликтует, неподходящий элемент исключает код |
| choiceType применяется при ведении КТРУ, не при применении | Сохраняет отдельно от kind | Не использует вместо kind |
| ОКЕИ значения необязателен | Сохраняет null; не подставляет шт | Число без единицы требует проверенной интерпретации, иначе unknown |
| «Количество бортов»: 1 OR 3; «Количество ребер жесткости»: ≥2 OR ≥4 OR ≥6, без ОКЕИ | Отдельный справочник по ID характеристики и проверенному имени, с происхождением actual-XML; трактовка count | Целые значения, исходный OR и границы; единица см не заменяет счёт |
| «Тип исполнения рукоятки»: числовые варианты без ОКЕИ | Не объявляет числовое обозначение физической величиной или счётом | Остаётся unknown; для интерпретации нужна отдельная проверка |
| isRequired=false | Невведённое необязательное неподдержанное поле — потенциальная диагностика | Не подтверждает его значение; не прекращает вопросы по другим проверяемым полям |
| Противоречивые границы исходного XML | Сохраняет raw и source_issues; не исправляет условие | Блокирует resolved независимо от заполнения |

Неподдержанная семантика сама по себе не объявляется дефектом данных.
Достоверный incompatible по другому правилу сохраняет приоритет; неизвестное
конкурирующее конечное положение не доказывает единственность.

43 настоящих позиции (40 конечных и 3 шаблона с source_issues) сверены с original actual-XML: kind, choiceType,
обязательность, весь набор характеристик, value_code, значения, единицы,
строгость границ, parent_code, is_template и noNewFeatures/null. XML-записи
и результаты сверки — [xml/sources.json](xml/sources.json), файлы в xml/.
Это проверка источника, а не ещё один рабочий XML-конвертер.

Ожидаемые варианты взяты из clean5 и сверены с XML, не из списков кодов в
алгоритме. Проверяется весь конечный пул области до ограничения выдачи.
Все POST используют настоящий Search и локальную E5, без подмены модели.
Явное подтверждение категории здесь отделяет проверку сужения от качества поиска.

После исправления нужный Check даёт compatible для допустимых наборов и
повторов. Неподходящий элемент даёт incompatible с его значением и причиной
в elements, позиция исключена; ручное подтверждение возвращает 422.
Проверенное свойство не спрашивается повторно. У киянки после проверки формы
доступно подтверждение настоящего кода; resolved требует всех защит API.
У других контрольных карточек продолжаются вопросы по обязательным полям
или различающим свойствам, а не прежний тупик multiple_choice_not_supported.

[edges.json](edges.json): допустимые 1/3 борта, недопустимые 2, дробное число,
см/ед вместо счёта, явно введённые шт, пустой интервал, OR ребер, введённое
непроверенное обозначение, обязательный пропуск и «не знаю». Семь позиций
с семью дефектными интервалами фактической clean5 (4 конечных и 3 шаблона)
сохраняют source-блокировки; подтверждение шаблонов также отклоняется с 422.
Пример: Сосуд Дьюара, Температура хранения: −100 < X ≤ −150; XML и raw не исправлены.

[stage1-repeat/after.json](stage1-repeat/after.json) повторяет пять сценариев
этапа 1. Лопата: 1 осталась / 2 исключены; молоток: 1 / 10; мужское пальто,
женское пальто и мужское 48 размера: каждый 1 / 1. Воскресших incompatible нет.
Подтверждение каждого проверенного исключённого кода — 422.

## Ограничения

Подключение всей поставки не означает полную поддержку всех ограничений:
непроверенные числовые обозначения и неподдержанные ОКЕИ остаются unknown,
дефекты источника и позиции без характеристик не получают resolved.
Два свойства без ОКЕИ интерпретированы проверенным справочником; общего правила
«число без единицы значит штуки/безразмерное» нет. Числовое designation
предусмотрено контрактом, но для рукоятки ещё не утверждено.
Неизвестный ответ не закрывает обязательное поле. Отсутствующий optional не
становится подтверждённым. Полнота графа не подменяет доказательство значений.
Старт полного каталога в текущем Docker занимает несколько минут; readiness
не ослаблен. Улучшение стратегии вопросов и интерфейса оставлено последующим этапам.
Сбой одного существующего браузерного теста остаётся для отдельного разбора.
