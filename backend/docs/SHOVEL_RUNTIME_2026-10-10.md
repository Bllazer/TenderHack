Backend использует существующие A/extraction, correction_flow, B/Search,
C/D через algorithm_adapter. Frontend, алгоритмы C/D, адаптер поставки и
готовые ML-артефакты не изменены. Доработка контракта описана в [API.md](API.md).

## Фактический HTTP сценарий

Вызовы проходят через frontend nginx `/api`, не через подменённый API:

- «лопата совковая»: категория требует подтверждения; после него
  `Тип лопаты=совковая`, raw=совковая, span=[7,15], status=needs_data,
  next_question=null, selected_ktru_code=null.
- «ловпата совкавая»: после категории correction для значения, span=[8,16],
  status=needs_input. Название товара автоматически не исправляется.
- «Лопата; Тип лопаты: Совкавая»: correction для значения, исходный
  фрагмент/span сохранён. Принятие → Совковая и полная перепроверка;
  отказ → исходные дополнительные сведения без выдуманного назначения.
  Обе ветки дают needs_data из-за указанных ограничений каталога.

Не запрашиваются поля, которые не могут устранить неподдержанную семантику.
Коррекция/конфликт имеют приоритет; после их разрешения blocker сохраняется.
Карточки доступны: GET `/api/v1/catalog/positions/{code}`.
Пользовательские facts отдельно от допустимых значений position.properties.

категорию, отрицания/неопределённость, принятие/отказ, конфликт после принятия,
явную замену значения, закрытие вопроса, карточку и причины блокировки.

26 passed. Первый локальный запуск с ../.tools/basetemp завершился 14 ошибками
создания временного каталога Windows; после использования backend/.tools
и доступных прав полный прогон прошёл.
Реальный HTTP smoke сверяет три записи с первоисточником; другие реальные типы
проверяет real_runtime_smoke: битум, огнеупорная глина, шпажки доходят до

Реальный Chromium без mock API: 15 сценариев прошли, включая пять проходов лопат,
принятие/отказ, смену категории, правку факта и «Не знаю». Docker build/up api
прошли фактически; live/ready/status через nginx возвращают 200, ready=true,
missing_resources=[]. Исходники frontend не изменены.

Из корня: `docker compose build api`, `docker compose up -d api`.
Frontend не пересобирается. Сервис оставляется работающим на
http://localhost:8080; Swagger http://localhost:8000/api/docs.
Перезапуск: `docker compose restart api`; остановка: `docker compose stop`.
Полные ответы и браузерный отчёт сохраняются локально в backend/.tools,
тяжёлые ресурсы и пользовательская поставка не добавляются в git.
